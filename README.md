# Редактор плана помещения

Локальный редактор планов помещений на FastAPI, ezdxf и PixiJS. Работает с PDF,
DXF, DWG и растровыми подложками: PDF используется для листов и визуального
сопоставления, а DXF/DWG — для CAD-геометрии, слоёв и блоков.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

После запуска откройте `http://127.0.0.1:8000`.

### Запуск для телефона в локальной сети

Остановите обычный сервер сочетанием `Ctrl+C`, затем запустите:

```bash
./scripts/run-local-network.sh
```

Скрипт покажет готовую временную ссылку вида
`http://192.168.1.38:8000/?editor=1&access_token=...`.
Откройте её на телефоне, подключённом к той же Wi-Fi/локальной сети. Если macOS
спросит о входящих подключениях для Python, разрешите их для частной сети.
При первом входе сервер запомнит доступ в защищённом cookie на 12 часов и уберёт секрет из адресной
строки. После перезапуска сервера будет создана новая ссылка.

В этом режиме приложение не публикуется в Интернете, но доступно другим устройствам
этой локальной сети. Не пересылайте временную ссылку и не используйте этот режим в гостевой или
недоверенной сети.

## Ручная корректировка плана

Нажмите **«Редактор плана»** в верхней панели. В режиме редактора доступны:

- **Выбор** — выбрать и перетащить стену, перегородку, дверь или окно;
- **Стена** — последовательно указать начало и конец стены;
- **Перегородка** — построить более тонкую внутреннюю стену;
- **Дверь ← / Дверь →** — создать дверь с нужной стороной открывания;
- **Двойная дверь** — создать двустворчатую дверь;
- **Окно** — добавить оконный проём с привязкой к стене;
- удаление выбранного элемента, отмена и повтор действий;
- привязка координат к сетке 10 px;
- регулировка прозрачности проектной подложки;
- сохранение в `data/geometry.json`.

Для выбранной стены или перегородки в карточке задаётся режим верха:
`фиксированная высота` или `до потолка зоны`. До появления контуров
потолочных зон в `heightMm` хранится текущая подтверждённая отметка. Раздел
`Состав по высоте` позволяет задать непересекающиеся полосы материалов,
например 0–1200 мм газоблока и 1200–2400 мм стеклоблока. На 2D-плане
высота показывается только у выбранного элемента, а 2.5D строит реальную высоту
и различает основные материалы цветом.

Горячие клавиши: `V` — выбор, `W` — стена, `P` — перегородка, `L` / `R` — одинарная дверь, `D` — двойная дверь, `O` — окно, `Delete` — удалить, `Ctrl/Cmd+Z` — отменить. Для прямого входа в редактор можно открыть `http://127.0.0.1:8000/?editor=1`.

API геометрии:

- `GET /api/geometry` — прочитать текущую модель;
- `PUT /api/geometry` — проверить и атомарно сохранить модель.

Удаление стены также удаляет привязанные к ней двери и окна, чтобы в модели не оставались «висячие» ссылки.

## Объёмный просмотр на том же листе

Сохраните геометрию и нажмите **Объём 2.5D** в заголовке плана. Модель читается из `/api/geometry`; построение не изменяет этот файл. При несохранённых правках приложение предложит сначала сохранить их.

- **План 2D** возвращает инструменты редактирования.
- Наклон считается от вида сверху: 0° — сверху, 70° — низкий ракурс. Есть пресеты 20°, 30°, 45°, 60° и шаг ±5°.
- Перетаскивание мышью вращает камеру, Shift или правая кнопка — сдвигает, колесо — масштабирует.
- **Весь план** или двойной щелчок возвращает масштаб и центр, сохраняя угол.
- Подложку PDF можно включить в объёмном виде для сопоставления.

Отрисовка выполняется локально на Canvas 2D с ортографической проекцией объёмных граней. Дверные и оконные проёмы вырезаются из стен; учитываются петли и число створок. Высоты условные в координатах плана, до калибровки метрического масштаба. Основание пока прямоугольное, замкнутый контур пола не вычисляется. Это базовый объёмный просмотр; фотореалистичные материалы и точные стыки стен требуют дальнейшей доработки.

Проверка геометрии объёмного режима: `node tests/plan-25d.test.cjs`.

## Архитектура, потолочные зоны и колонны

Редактор хранит архитектуру отдельно от исходной CAD-подложки. В 2D можно вручную
добавлять и редактировать стены, перегородки, двери и окна, а также круглые и
квадратные колонны. Для стен и перегородок задаются высота, режим «до потолка
зоны» и состав по высоте из нескольких полос материалов.

Потолочная зона создаётся как редактируемый многоугольный контур: вершины можно
перемещать, добавлять промежуточные углы и поворачивать участок под нужным углом.
Для зоны задаются тип потолка и отметка; высота стен в режиме «до потолка зоны»
берётся из неё. В 2.5D отображаются высоты, материалы, колонны и потолочные зоны.

## PDF, DWG и DXF

Кнопка **«Добавить исходный файл»** принимает PDF, DWG, DXF, PNG и JPG размером до
100 МБ. Кнопка **«Преобразовать в рабочий проект»** анализирует загруженные
источники и показывает найденные листы PDF, CAD-кандидаты и растровые подложки.

- **PDF** разбирается постранично: приложение строит миниатюры, предлагает листы
  для работы и позволяет использовать выбранный лист как заблокированную подложку
  в 2D/2.5D. PDF не превращается автоматически в редактируемые стены, двери или
  окна — архитектуру пользователь подтверждает и корректирует вручную.
- **DXF** читается напрямую через `ezdxf`; используются линии, полилинии, дуги,
  окружности, блоки и текстовые подписи.
- **DWG** временно конвертируется в DXF через локальный **ODA File Converter**,
  после чего проходит тот же разбор. На macOS конвертер автоматически ищется в
  `/Applications/ODAFileConverter.app`.
- CAD-подложка сохраняет пропорции и поворот, но вписывается в полотно с полями.
  Она заблокирована, поэтому редактируемые стены и оборудование не смешиваются с
  исходной геометрией.

Если ODA File Converter не установлен, DWG вернёт понятную ошибку, а DXF и PDF
продолжат работать. Неудачный разбор CAD не удаляет загруженный исходник.

## СОТ и потолочные камеры

В каталоге оборудования доступны два потолочных типа: **камера без кронштейна** и
**камера на кронштейне**. Камеру можно поставить на план, выбрать и перетащить,
изменить обозначение, высоту монтажа, длину кронштейна и направление.

Для камеры отдельно регулируются:

- поворот по плану;
- угол наклона вниз от горизонтали: `0°` — смотрит вдаль, `90°` — перпендикулярно
  полу вниз;
- угол обзора и дальность сектора;
- автоматическая или ручная мёртвая зона под камерой;
- пресет **«кассовая зона»** для быстрого перехода к виду почти вертикально вниз.

Сектор обзора показывается в 2D и 2.5D мягкой полупрозрачной заливкой. Стены и
колонны закрывают сектор, а дверные и оконные проёмы считаются проходами. Это
проектная визуализация: точная дальность и форма сектора требуют калибровки по
реальной высоте, фокусному расстоянию и характеристикам выбранной камеры.
Изменения камеры записываются отдельной кнопкой **«Сохранить камеры»**.

## DWG

`ezdxf` не читает DWG напрямую. Для DWG прототип использует локально установленный **ODA File Converter**: он временно конвертирует файл в DXF, после чего работает обычный парсер. На macOS приложение автоматически ищется в `/Applications/ODAFileConverter.app`. Если конвертера нет, API вернёт понятную ошибку; DXF продолжит работать.

## Как CAD-файл распознаёт оборудование

Прототип проверяет блоки `INSERT`, точки `POINT` и окружности `CIRCLE`. Объект считается контроллером или дверью, если в названии его слоя или блока есть, например:

- `SKUD`, `CONTROLLER`, `КОНТРОЛЛЕР`;
- `DOOR`, `GATE`, `ДВЕРЬ`, `ТУРНИКЕТ`.

Сейчас сама геометрия здания не извлекается из DXF: на экране остаётся демонстрационная схема, а найденные точки масштабируются по её границам. Для точного совмещения нужен реальный чертёж и его слои.
## Хранение нескольких проектов

В боковой панели «Мои проекты» можно создать пустой проект и открыть ранее сохранённый.
Перед переключением сохраните геометрию. Страница запоминает выбранный проект в параметре
`?editor=1&project=…` — эту ссылку можно добавить в закладки.

При первом обращении к списку текущие `data/project.json` и `data/geometry.json`
копируются в проект `initial`. Исходные файлы остаются нетронутыми.
Дальнейшие сохранения из нового интерфейса идут в `data/projects/<id>/project.json`.
Каждый проект содержит свою геометрию, метаданные, результаты чтения CAD и список исходников.
Загруженные файлы лежат рядом под уникальными именами; исходные названия видны в интерфейсе.
Проект `initial` пока использует существующую подложку `static/project-plan.png`.

«Добавить исходный файл» сохраняет PDF/DWG/DXF/PNG/JPG до 100 МБ в проект, но не
распознаёт стены и не меняет подложку. Кнопка «Преобразовать в рабочий проект»
анализирует исходники и показывает найденные листы PDF, CAD-кандидаты или растровые
подложки. Выбранный лист становится рабочей заблокированной подложкой проекта; уже
подтверждённые стены, двери и окна при этом не перезаписываются.

«Загрузить DXF / DWG» дополнительно запускает
существующий анализ оборудования. Он ищет подходящие названия слоёв/блоков и пока не
является автоматическим извлечением архитектуры. Координаты маркеров масштабируются
в поле плана, а не регистрируются по архитектурной подложке. Не считать их точной привязкой.
Неудачный разбор CAD не удаляет загруженный исходник.

После успешного чтения DXF/DWG приложение строит заблокированную `CAD-подложку` из
линий, полилиний, дуг, окружностей и содержимого блоков, а также переносит читаемые
текстовые подписи. Геометрия сохраняет пропорции и единый поворот, но автоматически
вписывается в полотно с полями. Это визуальный слой-источник: его нельзя случайно
переместить или удалить инструментами стен. Цветом различаются общий план, СОТ,
оборудование и пожарные слои. Изменяемые стены поверх него пользователь подтверждает
вручную; автоматическое распознавание стен и дверей остаётся следующим этапом.

Новые проекты исключены из Git через `.gitignore`: исходники заказчиков не попадут в push.
Это локальное хранилище, **не резервная копия и не синхронизация с Obsidian**.
Для резервного копирования нужны `data/projects/` и используемые подложки из `static/`.
Старые `/api/project` и `/api/geometry` оставлены для совместимости и работают со старыми
файлами: после обновления нужно перезагрузить редактор, чтобы сохранять в новое хранилище.
Совместное редактирование одного проекта из нескольких вкладок пока не поддерживается.

## СКУД и домофония

В редакторе используется презентационный набор обозначений: `СЧТ.` — считыватель,
`КНТ.` — контроллер доступа, `ЗМК.` — электромагнитный замок, `ОП.` — ответная
часть замка, `КВ.` — кнопка «Выход», `АВР.` — аварийная разблокировка, `МКД.` —
магнитоконтактный датчик, `ДОВ.` — доводчик, `БП.` — блок питания, `АКБ.` —
аккумулятор, `КС.` — соединительная коробка, `ВП.` — вызывная панель и `АУ.` —
абонентское устройство домофона. Старые проектные коды при открытии проекта
автоматически преобразуются в эти отображаемые обозначения.

Архитектурная дверь `D-*` и точка прохода СКУД `ТД.*` хранятся раздельно.
Дверь можно построить и сохранить без СКУД. Когда дверь нужно контролировать,
выберите её в 2D, введите код вида `ТД.1.1` и нажмите «Назначить точку прохода».
Точка прохода связывается с этой дверью и хранит число считывателей.

Для точного размещения выберите дверь с назначенной точкой прохода и откройте
«Монтажный узел · стороны А / Б». После этого приборы этой точки получают связанные
обозначения `СЧТ.1.1`, `КВ.1.1`, `АВР.1.1`, `ЗМК.1.1`, `МКД.1.1`, `ОП.1.1`,
`КС.1.1` и `ДОВ.1.1`.
В редакторе точки доступа выберите существующий прибор или добавьте новый, задайте
сторону, поверхность (стена, коробка, полотно) и положение кликом или перетаскиванием.
Числовая высота относится к центру прибора. Сторона Б зеркальна стороне А.
Кнопка «Заполнить по листу 6» создаёт типовой комплект по эскизу проекта: считыватель
со стороны коридора, а с защищаемой стороны — электромагнитный замок на коробке,
ответную часть замка на полотне, датчик двери, кнопку выхода, аварийную разблокировку,
дверной доводчик и соединительную коробку. Перед заполнением
выберите сторону А или Б: выбранная сторона считается коридором. Контроллер и блок
питания шаблон намеренно не размещает, поскольку на листе 6 их положение не задано.
Справочная панель «Проектный лист 6» показывается рядом с рабочей дверью: её можно
скрыть, увеличить кнопками или масштабировать `Ctrl/Cmd + колесо`. Изображение хранится
внутри текущего проекта и не подменяет редактируемую геометрию.
На рабочем виде три контрастные петли показывают сторону навески. При переходе со
стороны А на сторону Б петли зеркалятся; у двустворчатой двери они показаны по краям.
Рядом выводится индикатор «НА СЕБЯ» или «ОТ СЕБЯ» и неизменная сторона открывания
А/Б. Поэтому направление остаётся однозначным при просмотре двери с любой стороны.
«Применить к плану» переносит черновик в текущий проект; затем требуется «Сохранить оборудование».
Закрытие окна без применения отменяет его черновик. Старые приборы требуют уточнения монтажа.
Привязанные приборы перемещаются через этот редактор: их координаты вычисляются
от двери и хранятся для детального узла. На общем 2D-плане вместо подписей всех приборов
показывается один компактный знак `ТД.*`; в 2.5D весь дверной узел также сворачивается в одно
схематичное обозначение. Контроллеры, блоки питания и прочее самостоятельное оборудование
остаются отдельными объектами.
Масштаб пока условный (20 мм на единицу плана); проверка близости приборов базовая,
точные габариты и составные модели замка/датчика ещё не реализованы.

Для презентационного рендера одной двери виды А и Б считаются изображениями одного
физического узла, а не независимыми сценами. Перед выдачей обязательно проверяются:

- зеркальное соответствие стороны петель, ручки и направления открытия на двух видах;
- видимое соединение каждой петли одновременно с коробкой и полотном;
- корпус электромагнитного замка закреплён на коробке, а отдельная ответная пластина —
  на полотне и совмещается с корпусом при закрытии;
- рабочая полюсная поверхность магнита направлена к ответной пластине; наружу показана
  тыльная часть корпуса, а не рабочая плоскость;
- замок и доводчик показаны только с той стороны, где они действительно установлены;
- считыватель, кнопки и прочие приборы имеют реалистичный размер относительно двери.
- каждый видимый кабель или кабель-канал непрерывно доходит до прибора либо явно уходит
  в скрытую трассу — декоративные оборванные линии запрещены;

Состав сторон берётся из листа 6: со стороны коридора показан считыватель, со стороны
защищаемого помещения — замок, доводчик, аварийная разблокировка и кнопка выхода.
Отсутствие внутренних приборов на коридорном виде не считается ошибкой и не должно
компенсироваться выдуманным дублированием оборудования.

Если генератор изображения нарушил хотя бы один пункт, такой рендер не используется как
техническая иллюстрация, даже если визуально он выглядит убедительно.

В режиме «Редактор плана» доступен отдельный каталог оборудования: точка доступа,
контроллер, считыватель, кнопка выхода, аварийная разблокировка, замок, датчик двери,
блок питания, аккумулятор, соединительная коробка, вызывная панель и монитор домофона.

Для двери отдельно задаётся один считыватель («вход по карте, выход по кнопке») или два
считывателя («вход/выход»). В карточке контроллера задаются ёмкость по дверям и по
считывателям и отмечаются все обслуживаемые точки доступа. Одна дверь не может быть
назначена двум контроллерам, а превышение любой из двух ёмкостей блокируется.

Форм-фактор контроллера и место монтажа независимы. Контроллер на DIN-рейку можно
разместить в шкафу, в локальном настенном боксе или в боксе за потолком. Сам модуль
крепится на DIN-рейку внутри оболочки, а не непосредственно на строительную поверхность.
Координата на плане показывает фактическое место контроллера, а список обслуживаемых
дверей — его логические связи.

Выберите прибор и нажмите на план. Дверные устройства можно поставить только рядом с
уже созданной дверью — приложение сохранит связь с её идентификатором. Контроллеры,
источники питания и другие настенные узлы получают ближайшую стену, если она находится
рядом. Размещённый объект выбирается и перетаскивается как отдельный элемент. В карточке
можно изменить обозначение, способ и высоту монтажа, связанную дверь и статус
`Предложено`/`Подтверждено`. Для записи используйте отдельную кнопку «Сохранить
оборудование».

Архитектура и оборудование хранятся независимо, но связанные объекты ведут себя
согласованно: прибор перемещается вместе с дверью или стеной, а удаление связанной
архитектуры блокируется до ручной отвязки. Красный используется только для аварийной
разблокировки. В 2.5D дверные точки прохода показываются одним обозначением `ТД.*`, а отдельное
оборудование — как небольшие объёмные модели с проектными обозначениями. Высота и способ монтажа
берутся из карточки. Потолочные
приборы размещаются под условной плоскостью потолка. Кабельные трассы, материалы и детальные
каталожные 3D-модели остаются следующими этапами.

Проверки без изменения пользовательских проектов:

```bash
.venv/bin/python tests/test_projects.py
node tests/editor-interactions.test.cjs
node tests/plan-25d.test.cjs
```

Для быстрой проверки синтаксиса фронтенда также используются:

```bash
node --check static/app-v2.js
node --check static/plan-25d.js
```

## Ограничения и ближайшие этапы

- автоматическое извлечение стен, дверей и помещений из CAD пока не заменяет ручное
  подтверждение архитектора;
- масштаб и высоты в 2.5D остаются условными, пока не задана метрическая калибровка;
- сектор камеры и мёртвая зона являются наглядной инженерной моделью, а не расчётом
  сертифицированного покрытия;
- кабельные трассы, ведомости материалов, экспорт монтажной документации и детальные
  каталожные 3D-модели оборудования ещё не реализованы;
- совместное редактирование одного проекта из нескольких вкладок и история версий
  пока не поддерживаются.

PDF остаётся исходным листом/подложкой, а редактируемая модель помещения строится
поверх него вручную и сохраняется отдельно.
