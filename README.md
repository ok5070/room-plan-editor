# Редактор плана помещения

Локальный прототип на FastAPI, ezdxf и PixiJS. Принимает DXF и DWG.

## Запуск

```bash
cd sibest-dashboard
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

После запуска откройте `http://127.0.0.1:8000`.

## Ручная корректировка плана

Нажмите **«Редактор плана»** в верхней панели. В режиме редактора доступны:

- **Выбор** — выбрать и перетащить стену, перегородку, дверь или окно;
- **Стена** — последовательно указать начало и конец стены;
- **Перегородка** — построить более тонкую внутреннюю стену;
- **Дверь ← / Дверь →** — создать дверь с нужной стороной открывания;
- **Двойная дверь** — создать двустворчатую дверь;
- **Окно** — добавить оконный проём с привязкой к стене;
- удаление выбранного элемента, отмена и повтор действий;
- привязка координат к сетке 10 px;
- регулировка прозрачности проектной подложки;
- сохранение в `data/geometry.json`.

Горячие клавиши: `V` — выбор, `W` — стена, `P` — перегородка, `L` / `R` — одинарная дверь, `D` — двойная дверь, `O` — окно, `Delete` — удалить, `Ctrl/Cmd+Z` — отменить. Для прямого входа в редактор можно открыть `http://127.0.0.1:8000/?editor=1`.

API геометрии:

- `GET /api/geometry` — прочитать текущую модель;
- `PUT /api/geometry` — проверить и атомарно сохранить модель.

Удаление стены также удаляет привязанные к ней двери и окна, чтобы в модели не оставались «висячие» ссылки.

## Объёмный просмотр на том же листе

Сохраните геометрию и нажмите **Объём 2.5D** в заголовке плана. Модель читается из `/api/geometry`; построение не изменяет этот файл. При несохранённых правках приложение предложит сначала сохранить их.

- **План 2D** возвращает инструменты редактирования.
- Наклон считается от вида сверху: 0° — сверху, 70° — низкий ракурс. Есть пресеты 20°, 30°, 45°, 60° и шаг ±5°.
- Перетаскивание мышью вращает камеру, Shift или правая кнопка — сдвигает, колесо — масштабирует.
- **Весь план** или двойной щелчок возвращает масштаб и центр, сохраняя угол.
- Подложку PDF можно включить в объёмном виде для сопоставления.

Отрисовка выполняется локально на Canvas 2D с ортографической проекцией объёмных граней. Дверные и оконные проёмы вырезаются из стен; учитываются петли и число створок. Высоты условные в координатах плана, до калибровки метрического масштаба. Основание пока прямоугольное, замкнутый контур пола не вычисляется. Это базовый объёмный просмотр; фотореалистичные материалы и точные стыки стен требуют дальнейшей доработки.

Проверка геометрии объёмного режима: `node tests/plan-25d.test.cjs`.

## DWG

`ezdxf` не читает DWG напрямую. Для DWG прототип использует локально установленный **ODA File Converter**: он временно конвертирует файл в DXF, после чего работает обычный парсер. На macOS приложение автоматически ищется в `/Applications/ODAFileConverter.app`. Если конвертера нет, API вернёт понятную ошибку; DXF продолжит работать.

## Как CAD-файл распознаёт оборудование

Прототип проверяет блоки `INSERT`, точки `POINT` и окружности `CIRCLE`. Объект считается контроллером или дверью, если в названии его слоя или блока есть, например:

- `SKUD`, `CONTROLLER`, `КОНТРОЛЛЕР`;
- `DOOR`, `GATE`, `ДВЕРЬ`, `ТУРНИКЕТ`.

Сейчас сама геометрия здания не извлекается из DXF: на экране остаётся демонстрационная схема, а найденные точки масштабируются по её границам. Для точного совмещения нужен реальный чертёж и его слои.
